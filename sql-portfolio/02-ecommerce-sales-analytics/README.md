# E-Commerce Sales Analytics — SQL Mini Project

An intermediate SQL project simulating an online store's order history over
6 months. Focused on **CTEs and window functions** — the tools you actually
reach for when doing analytics work: running totals, rankings, growth rates,
and cohort-style new-vs-returning breakdowns.

## 📊 Schema

- `customers` — signup date, country
- `products` — category, unit price
- `orders` — one row per order, with status (completed/cancelled)
- `order_items` — line items per order (quantity + price at time of sale)

## 📁 Files

| File | Purpose |
|---|---|
| `ecommerce_sales_analytics.sql` | One self-contained file: schema, seed data (15 customers, 10 products, 39 orders across Jan–Jun 2023), all 9 analytical queries, and each query's real output |

## 🚀 Setup

```bash
createdb ecommerce_analytics
psql -d ecommerce_analytics -f ecommerce_sales_analytics.sql
```

The output comments in the file were generated by actually running this exact
schema and data — they're not hand-written guesses. Re-running the file
yourself should reproduce the same results.

## 🧠 What this project demonstrates

- Structuring multi-step logic with `WITH` (CTEs) instead of nested subqueries
- `LAG()` for month-over-month growth and days-between-orders
- `SUM() OVER (ORDER BY ...)` for running totals
- `RANK()` / `DENSE_RANK()` for top-N-per-group and leaderboard-style queries
- `AVG() OVER (PARTITION BY ...)` to compare a row against its group's average
- `FILTER (WHERE ...)` for conditional aggregation (new vs. returning customers)
